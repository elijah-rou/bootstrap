# ADR-002: Native selections and uninstall ownership

Status: accepted

## Context

Bootstrap is used on machines where personal credentials and sessions must be removable without treating the whole home directory or package database as owned. Native package managers can also install packages that later become shared. Language and LSP coupling made implicit installation impossible to audit.

## Decision

The public CLI has independent `--languages`, `--lsp`, and `--tools` selectors. Selections and cleanup identities use one schema-versioned record at `${XDG_STATE_HOME:-~/.local/state}/bootstrap/install.json`; `packages/catalog.json` is the single package/executable/LSP mapping. Configuration-only entry points remain offline and unprivileged.

The record is written before managed mutations. It stores a random installation ID, component and overall readiness, selections, exact managed targets, original file/link state, enrolled roots and package pre-presence/version. Records and paths are bounded and validated. Targets must be below the current home, cannot be the home itself, and cannot escape through symlink ancestors. The only exception is the fixed `lua/plugins/zz-bootstrap-managed.lua` symlink in an explicitly supplied external Neovim checkout: the journal records the checkout device/inode and canonical path, rejects symlink parents and tracked/custom collisions, and may remove only an unchanged managed link. The checkout is never enrolled or recursively cleaned. Unknown schemas fail closed. A non-stealable directory lock serializes mutation.

`scripts/bare-env.sh` is the single runtime path contract for install, offline configure, and ordinary Bash/Zsh launches. Pi entrypoints load the owned profile, invoke the installed CLI directly, and use `PI_CODING_AGENT_DIR` plus the supported `--session-dir` argument. Selected Codex uses `CODEX_HOME` within the enrolled private root; offline instruction-only configuration keeps its existing scope. Neovim uses `NVIM_APPNAME=bootstrap-nvim`, with separately enrolled data/cache/state roots. Workstation overlays change configuration composition and the persisted editor profile only; they do not change ownership roots or opt into Zsh, Starship, Mason, or incidental LSPs. Herdr has no profile-root override, so its supported `~/.config/herdr` root is enrolled only when fresh or provably managed; unrelated existing state blocks adoption. Project copies require an exact explicit enrollment command and confirmation. The legacy tools prefix is preserved because ownership cannot distinguish user additions from old bootstrap content.

Uninstall defaults to deleting enrolled private state and eligible bootstrap-added packages. It previews first, refuses processes identified by the owned runtime path or matching private-profile environment and changed shared files, restores recorded originals, does not follow enrolled symlinks, previews dependency effects, preserves pre-existing/shared packages, and never runs blanket autoremove or downgrade. Progress is recorded after each inverse operation so interruption is retryable. Preview does not acquire a mutation lock, write a journal, stop services, or request elevation. Real tmux control uses explicit sockets under the enrolled private root; Herdr control requires its own enrolled root. A single already-loaded Node process remains the cleanup controller through native/runtime deletion. It verifies every resource restoration, backup removal, enrolled root, and package result before removing control/recovery state. The former unused `writers` field is not a liveness contract.

Native removal executes exact-name `dpkg --remove --` on apt hosts and `rpm -e --` on dnf hosts, with dependency checks enabled. Unlike the expanding frontend solvers, these transactions refuse a new dependent that appears after preview. Apt simulation remains the apt preview; Fedora preview reads RPM provided, file, and required capabilities without invoking DNF, whose preview writes logs/cache. Rich requirements and alternate providers may conservatively block removal. Query or parse failure blocks cleanup. Pacman and Homebrew keep their non-cascading dependency checks.

These exact backend operations update the native package database but do not create an apt/DNF frontend-history transaction. No automatic rollback through frontend history is promised. `dpkg --remove` retains conffiles; bootstrap reports that residual state rather than purging modified/shared native configuration. Bootstrap-enrolled personal files are still removed according to their independent ownership record.

Tool-specific state uses supported controls: npm `cache` (`npm_config_cache`), uv `UV_CACHE_DIR`, `UV_PYTHON_INSTALL_DIR`, `UV_PYTHON_BIN_DIR`, `UV_TOOL_DIR`, and `UV_TOOL_BIN_DIR`; Go `GOCACHE`, `GOMODCACHE`, and `GOENV`; Mix `MIX_HOME` and `MIX_INSTALL_DIR`; Hex `HEX_HOME`. These point below enrolled roots without changing other applications' XDG paths. ElixirLS preparation runs at its final installed path under a 600-second bound and reuses those caches on retry.

Go's `GOTELEMETRYDIR` is output-only. Before Go/gopls invocation, bootstrap claims a fresh `~/Library/Application Support/go/telemetry` on macOS or `${XDG_CONFIG_HOME:-~/.config}/go/telemetry` on Linux. This is enrolled shared-location state, not isolated telemetry. Existing unenrolled directories and symlinks block selection. The journal records the directory identity before it can be used; replacement or an interrupted ambiguous claim blocks cleanup. Explicitly enrolled existing state retains the user's authorized deletion scope.

References: [uv environment variables](https://docs.astral.sh/uv/reference/environment/), [Go environment](https://pkg.go.dev/cmd/go#hdr-Environment_variables), [Mix environment](https://hexdocs.pm/mix/Mix.html#module-environment-variables), [Hex configuration](https://hexdocs.pm/hex/Mix.Tasks.Hex.Config.html), and [npm cache](https://docs.npmjs.com/cli/v11/using-npm/config#cache).

## Consequences

Core no longer depends on Python, Conda, Zsh, Starship, or an activation shell. Existing personal Herdr state and ambiguous legacy symlinks require operator action rather than unsafe adoption. Filesystem cleanup cannot provide secure erasure or revoke remote credentials. GitHub CLI may use a shared OS credential-store entry keyed by host/account, independent of `GH_CONFIG_DIR`; bootstrap does not delete those entries. Installation requires no authentication, and a stored-auth policy is still a separate blocking decision. Publishing still requires advancing the separate launcher revision and archive digest after the runtime commit is public and verified.
