# agent-kit pin

Moves bootstrap's agent-kit pin to a commit on agent-kit's main and opens the pull request, or reports that the pin is current. `scripts/pin-agent-kit` does every step; this file says when to run it and what it leaves to others. It never merges.

## Trigger

An agent-kit landing run (the `ship` or `autopilot-full` mode in agent-kit), once after its last agent-kit merge, with no commit argument, so the pin moves to agent-kit's main in one pull request. Every pin rewrites the same catalog row, so pinning after each merge would open pull requests that conflict with one another. By hand, from a clone of this repository:

```sh
scripts/pin-agent-kit --dry-run          # preview against agent-kit's current main
scripts/pin-agent-kit                    # pin agent-kit's current main
scripts/pin-agent-kit <40-hex commit>    # pin a given commit on agent-kit's main
```

## Gates (the script checks these and changes nothing)

- The commit is not a full 40-character hex commit reachable from agent-kit's main: exit 2.
- `origin/main` already pins it: it prints that the pin is current and exits 0.
- An open pull request from this repository's own `agent/pin-agent-kit-<12-char sha>` branch: it prints that pull request's URL and exits 0. Pull requests from forks never count, whatever their branch is named.
- Another open pin pull request from this repository (an `agent/pin-agent-kit-*` branch for a different commit): it names that pull request and exits 1. Land or close it first.
- A pushed branch of that name without an open pull request is reused only when it pins the commit; anything else stops the run for a person to inspect it.

## What the script changes

- `catalog.tsv`: the agent-kit row's version. `scripts/pin` refuses agent-kit, so this script is the one path that moves the pin.
- `pi/agents/autopilot-owner.md`: a generated body. It becomes agent-kit's `claude/agents/autopilot-owner.md` at that commit, with "escalate anything outside the brief in your report." replaced by the Pi wording "through the supervisor". If agent-kit drops that sentence, the run stops and names the substitution to update. The Pi frontmatter stays bootstrap's, and its `# Body generated by scripts/pin-agent-kit from agent-kit <commit> ...` line names the commit; `scripts/validate` (through `scripts/check-agent-kit-role`) fails when that commit is not the catalog's pin. If the body differs from what the current pin generates, someone edited it by hand: the run stops rather than erase that text.

Nothing else a pin may need is detected: an agent-kit change to a path `install.sh` links, or a new role or extension that needs bootstrap wiring, needs a bootstrap change of its own. The pull request lists the agent-kit commits since the old pin for that review.

## Boundaries

- `scripts/validate` must pass in the pin worktree before anything is committed or pushed. The install round trip is left to CI and the verifier.
- The script opens the pull request ready for review, but it changes configuration and agent instructions, so it lands only through an agent-kit landing mode (`ship`, `autopilot-stack`, or `autopilot-full`) after that mode's verification round with its audit lane (the adversarial pull-request review) at the pull request's head. No exemption like `catalog-bumps`' applies.
- This run never records a verdict. Landing needs one from a fresh verifier, a separate session, that drives the install at the pull request's head; whoever lands follows the verdict gate in the installed `babysit-and-ship` skill.
- One commit per run. Never merge, deploy, or release.

## Report

The script's exit status and last line (`scripts/pin-agent-kit --help` has the full contract): 0 with the pull request's URL, the "agent-kit pin is current" line, or the dry-run line on stdout; 1 for a failure, with the reason on stderr (another open pin pull request is named there); 2 for a usage error or a commit agent-kit's main does not reach.
